# T.A.R.O. - Risks and Troubleshooting

**Version:** 1.2.0 (Draft)

No design is free of faults. This file lists the faults most likely to appear, how the design reduces each, how you will notice it, and what to do. Add every new problem you meet here in the same change that fixes it (RULES section 18).

---

## 1. What These Docs Cannot Promise

- They cannot prove the code works before it exists. The acceptance tests in TASKS.md do that.
- Numbers (tokens/s, VRAM, accuracy of skill generation) are **estimates until the benchmark tasks run** (TASK-011, TASK-021, TASK-113, TASK-090).
- A small local model makes mistakes. The design catches mistakes with code (schema checks, risk gate, status block). It does not assume the model is right.
- Windows updates, app updates, and library updates can break automation. The evaluation harness is how you find out quickly.

## 2. Risk Register

Likelihood and impact: L = low, M = medium, H = high.

## 3. Troubleshooting

| Symptom | Likely cause | What to do |
| :--- | :--- | :--- |
| `ollama run taro` says model not found | `ollama create` not run or base tag wrong | `ollama list`; confirm the base tag; rerun `ollama create taro -f config/Modelfile` |
| Very slow replies | Model spilling to CPU or two models loaded | `ollama ps`; set `OLLAMA_MAX_LOADED_MODELS=1`; close GPU-heavy apps; lower `num_ctx` or try the 4B model |
| "CUDA out of memory" | Chat and vision loaded together or a game using the GPU | Check `nvidia-smi`; ensure vision unloads; close other GPU programs |
| Replies contain `<think>` text | Thinking mode on | Send `think: false` in the API request; fallback `/no_think`; check the stripper is active |
| Tool never called, model only talks | Tool not in the loaded set | Use `find_tools`; check category filter; check the tool is enabled in Settings |
| Tool called with wrong arguments | Small model error | Look at the repair retry in the audit log; tighten the tool description; add an example to the schema |
| "Action FAILED" but model says it worked | Model prose disagrees with the status block | Trust the status block; report the case to add to the evaluation harness |
| HUD blank or does not open | WebView2 missing | Install the WebView2 runtime |
| HUD loads but nothing responds | Token or port mismatch | Restart T.A.R.O.; check `logs/core` for a refused-origin message |
| Camera preview black | Windows camera privacy setting or another app using the camera | Settings > Privacy > Camera; close the other app; try the OpenCV fallback |
| OCR returns empty text | Tesseract not on PATH | `tesseract --version`; add the install folder to PATH |
| Wake word never triggers | Missing "taro" model file or wrong mic | Check `models/`; run the mic test; use push-to-talk |
| Wake word triggers on TV or music | Threshold too low | Raise the threshold in config; train the model with more negative samples |
| Hotkey kill does nothing | Elevated window has focus | Use the HUD or tray kill button, or run `taro kill` |
| Memory search fails offline | Embedding model not bundled | Confirm `models/` contains the embedding model (MEMORY 12) |
| "Audit chain broken" at startup | Log edited, truncated, or disk error | Read the reported line number; export the log; decide whether it was you; the app keeps running but marks the log untrusted |
| "Protected file changed" at startup | `core/` or permissions file modified | Check `git status`; restore the file or re-run `scripts\protect_install.bat` if the change was intentional |
| Skill rejected by static check | Import or call not allowed | Read the reported line; ask for a version without it, or add the module to the allowlist yourself if you accept the risk |
| Skill killed with "limit exceeded" | Time or memory limit | Raise the limit in the skill's `skill.json` after reading what the skill does |
| Defender flags the EXE | Input-hook libraries look suspicious | Use the onedir build; follow the allowlist steps in `docs/security-review.md`; sign the build |
| `pip install` fails with a compiler error | Package has no wheel for your Python | Install Microsoft C++ Build Tools, or use the wheel variant (for example `webrtcvad-wheels`) |
| Automation worked yesterday, fails today | App or Windows update changed the UI | Run `ui.act` with verification and read the failing step; update the shortcut or element name; add a regression case |

## 4. How to Use This File

1. When something fails, find the closest row above and follow it.
2. If it is not listed, find the cause, fix it, and add a row to Section 2 or 3 in the same change.
3. Before a release, run the evaluation harness (TASK-146), the doc check (`scripts/check_docs.py`), and `main.py --doctor`.
